# OnCue 产品优化方案

> 状态：执行提案  
> 版本：1.0  
> 日期：2026-08-26  
> 适用范围：产品、体验、商业化、营销、定价、用户增长与发布治理  
> 首发对象：个人求职者  
> 核心定位：本地优先、用户自带 API Key 的实时面试副驾

## 1. 文档目的

本文把现有产品审计、商业化检查和竞品研究收敛为一份可执行方案，解决四个问题：

1. 用户为什么下载，首次打开后怎样尽快获得价值。
2. 实时面试副驾如何成为清晰、可信、可复用的核心产品。
3. 在不建设账号和自营模型后端的前提下，怎样完成首轮收费。
4. 产品达到什么条件后，才值得扩大营销和增长投入。

本方案吸收但不覆盖以下草案：

- [PRODUCT_LAUNCH_PLAN.md](PRODUCT_LAUNCH_PLAN.md)
- [copilot-vs-suite.md](research/copilot-vs-suite.md)

若两份草案存在冲突，以本文的产品顺序为准：

> 实时 Copilot 是核心价值；简历优化和模拟面试负责准备、校准与留存，不取代核心。

本文只定义优化范围和验收标准，不要求删除已实现模块，也不要求首期重构应用架构。

## 2. 决策摘要

### 2.1 产品一句话

> 本机实时听懂面试问题，结合你的简历和目标岗位，给出可以直接说出口的回答建议。

英文建议：

> A local-first desktop interview copilot that turns live questions into answers grounded in your experience.

### 2.2 次级承诺

- 支持 macOS 和 Windows。
- 用户自带模型和语音服务 API Key。
- Rabbit 不建设第一方面试内容后端。
- 简历、职位资料、历史和录音默认保存在本机。
- 内容直接发送给用户选择的 AI 或语音服务商。

禁止使用下列绝对化表述：

- “面试内容完全不离开电脑。”
- “绝对不可检测。”
- “适用于任何面试规则。”
- “保证通过面试。”

原因：真实运行中，音频、转写、简历和职位描述可能发送给 Deepgram、OpenAI、Anthropic、Gemini、Groq 等用户选择的第三方服务。

### 2.3 首发商业模型

只推出两档：

| 方案 | 建议价格 | 权益 |
|---|---:|---|
| 免费版 | ¥0 / $0 | 完整安装与兼容性检查；简历优化；模拟面试；本地历史；实时 Copilot 10 分钟体验 |
| 求职季卡 | ¥199 / $39，90 天 | 实时 Copilot 不限 Rabbit 使用时长；更新；优先问题反馈；仍由用户承担第三方 API 成本 |

首发暂不提供：

- 月卡。
- 终身版。
- 多档套餐。
- 按 credits 计费。
- Rabbit 托管模型额度。
- 团队版和企业版。

只有出现至少 50 位真实付费用户，并能观察到明确的复购或跨求职季需求，才重新评估月卡和终身版。

### 2.4 北极星指标

首要激活指标：

> 新用户在首次启动后 15 分钟内，成功听到系统音频并获得第一条有用的实时建议。

“有用”在首期采用显式用户反馈定义：建议出现后，用户点击“有帮助”或在测试会话结束时选择“建议可用”。

首期不使用打开应用、填写 API Key 或进入 Copilot 页面作为激活。

## 3. 当前产品基线

### 3.1 已有能力

当前代码已经具备完整产品骨架：

- Dashboard、Copilot、模拟面试、简历优化、历史和设置六个模块。
- 多模型供应商和 STT 配置。
- 系统音频与麦克风捕获。
- 基于简历、职位描述和最近对话生成实时建议。
- Copilot 自动归档、评分和本地 SQLite 历史。
- 模拟面试、逐题反馈和综合报告。
- PDF/DOCX 简历导入、岗位匹配、事实复核和 DOCX 导出。
- 历史搜索、录音回放、转写和 PDF 导出。
- Tauri 更新能力和跨平台发布工作流基础。

因此，方案优先复用现有模块和数据结构，不新建一套平行产品。

### 3.2 阻碍商业化的主要问题

| 层级 | 当前问题 | 用户后果 | 商业后果 |
|---|---|---|---|
| 激活 | 无首次配置向导，Dashboard 说明与真实依赖不一致 | 用户不知道需要模型和 STT 两套配置 | 下载无法转化为首次成功 |
| 信号 | 侧栏 AI Engine 常绿，能力加载失败也可能显示就绪 | 用户在错误状态下开始面试 | 首次失败直接损害信任 |
| 上下文 | Copilot 没有统一岗位/公司身份，且仍优先原始简历 | 回答不够针对目标岗位 | 核心价值弱于竞品 |
| 会话 | 默认同时开系统音频和麦克风，Clear 无确认 | 回声、重复说话人或误清空 | 实战可靠性不足 |
| 复盘 | 已保存 strengths、improvements、summary，但 History 不展示 | 用户看不到进步价值 | 留存和付费理由变弱 |
| 指标 | 噪声或空会话也进入统计 | Dashboard 数据不可信 | 无法判断真实使用和留存 |
| 安全 | API Key 仅静态 seed XOR，未使用系统 Keychain | 敏感凭据保护不足 | 不适合公开收费 |
| 分发 | updater 指向私有且落后的仓库，匿名访问 404 | 外部用户无法稳定更新 | 公开获客闭环中断 |
| 签名 | macOS 未公证，Windows 未签名 | 安装警告和拦截 | 付费转化受阻 |
| 商业 | 无许可证、试用、权益和支付闭环 | 无法收费 | 只能停留在演示产品 |
| 增长 | 无最小事件漏斗 | 不知道用户在哪一步流失 | 营销预算无法优化 |

## 4. 目标用户与使用场景

### 4.1 核心用户

首发只服务一类用户：

> 正在 1 至 3 个月集中求职，希望在远程面试中得到实时提示，愿意自行配置 API Key，并重视本地数据控制的个人求职者。

优先细分：

- 软件工程、数据、产品、设计和运营岗位。
- 使用 macOS 或 Windows 参加 Zoom、Google Meet、Teams、腾讯会议等远程面试。
- 已有简历和目标职位描述。
- 对订阅疲劳敏感，但愿意为一个求职季付费。

暂不优先：

- 不愿配置任何 API Key 的大众用户。
- 企业招聘方。
- 培训机构多人管理。
- 手机端现场面试。
- 纯刷题或纯编码面试工具用户。

### 4.2 核心 Job to Be Done

> 当我参加重要远程面试时，我希望软件能可靠听懂对方的问题，结合我的真实经历和目标岗位快速给出可表达的回答框架，让我减少卡顿，同时不把完整面试材料交给 Rabbit 的服务器。

### 4.3 三个使用阶段

1. 面试前：建立 Interview Profile，检查音频和模型，进行一次短模拟。
2. 面试中：实时识别问题，生成基于本人经历的建议，尽量减少干扰。
3. 面试后：自动归档、展示强项和改进项，并为下一次练习提供行动建议。

## 5. 目标信息架构

保留现有六个主导航，不进行高成本导航重构。通过默认入口和页面串联建立清晰主线：

1. Dashboard：今天是否准备好，以及下一步动作。
2. Copilot：核心实时工作台。
3. Mock：使用同一 Interview Profile 进行热身。
4. Resume：维护简历、职位描述和目标岗位。
5. History：复盘真实与模拟会话。
6. Settings：供应商、音频、隐私、存储和许可证。

统一资产定义为 Interview Profile，不新建独立数据库模块。首期直接扩展现有简历工作区：

- resumeOriginal
- resumeOptimized
- jobDescription
- targetRole
- targetCompany
- lastUpdatedAt

Copilot 和 Mock 读取同一 Profile，减少重复配置和上下文漂移。

## 6. 目标用户流程

### 6.1 首次启动

1. 欢迎页说明产品工作方式、第三方数据流和 BYOK 成本。
2. 选择模型供应商并测试 Key。
3. 选择 STT 供应商并测试 Key。
4. 检查麦克风、系统音频和必要权限。
5. 导入简历或选择稍后处理。
6. 进入 60 秒音频测试。
7. 获得第一条建议后进入 Dashboard。

用户可跳过简历，但不能在没有完成模型、STT 和音频检查时看到“系统已就绪”。

### 6.2 面试前

1. 从 Dashboard 选择已有 Interview Profile。
2. 确认岗位、公司、职位描述和使用的简历版本。
3. 运行 60 秒快速测试。
4. 可选进行 3 题快速模拟。
5. 开始 Copilot。

### 6.3 面试中

1. 默认只捕获系统音频。
2. 用户主动开启麦克风后才进行双路捕获。
3. 页面持续显示四类状态：音频、STT、模型、保护能力。
4. 每条建议标明生成中、成功或失败。
5. 网络或供应商失败时保留已转写内容，并提供原地重试。
6. 停止或关闭窗口前保存可恢复的会话快照。

### 6.4 面试后

1. 自动生成标题：目标公司 + 目标岗位 + 日期。
2. 展示分数、强项、改进项、摘要和下一步练习。
3. 用户确认这是否是一次有效会话。
4. 有效会话进入 Dashboard 统计；音频测试和噪声会话不计入。
5. 用户可从历史页再次进行同岗位模拟或开始下一次 Copilot。

## 7. 分阶段执行方案

### 阶段 0：冻结范围与建立基线

时间：第 1 周前 1 至 2 天  
目标：避免功能继续扩散，让后续数据可比较。  
优先级：P0

### 范围

- 确认实时 Copilot 为首发核心。
- 确认免费版 + 90 天求职季卡为唯一首发定价。
- 记录当前版本、构建状态、安装包状态和关键流程。
- 定义下文统一指标和事件字典。
- 把现有两个草案标记为输入资料，不并行维护相互冲突的路线。

### 不做

- 不改导航结构。
- 不删 Mock 或 Resume。
- 不建设账号、云后端或支付 API。
- 不开始付费广告。

### 验收

- 产品、开发和营销使用同一句产品定位。
- 每个需求都有负责人、目标版本和验收方式。
- 当前下载、首次配置、首次建议、第二次有效使用基线可记录。

### 阶段 1：首次激活与真实就绪状态

时间：第 1 至 2 周  
目标：让新用户在 15 分钟内完成首次成功。  
优先级：P0

### 1.1 建立统一 Readiness 状态

复用现有 settings、供应商测试和 capability 检查，生成派生状态，不创建第二套真相。

状态：

| 状态 | 定义 | UI 行为 |
|---|---|---|
| loading | 设置或系统能力尚未加载 | 禁止显示绿色就绪 |
| unconfigured | 缺少当前模型或 STT 必需配置 | 显示缺失项和直达设置 |
| testing | 正在检查 Key、音频或权限 | 显示进度，不允许重复提交 |
| ready | 当前选定链路全部通过 | 允许开始 Copilot |
| degraded | 某个可选能力失败，但核心路径可用 | 明确说明降级内容 |
| error | 核心能力失败 | 禁止开始并提供修复动作 |

代码落点：

- [src/App.tsx](../src/App.tsx)
- [src/pages/Dashboard.tsx](../src/pages/Dashboard.tsx)
- [src/pages/StealthCopilot.tsx](../src/pages/StealthCopilot.tsx)
- [src/pages/Settings.tsx](../src/pages/Settings.tsx)
- [src/lib/settingsStore.ts](../src/lib/settingsStore.ts)

最小实现原则：

- 从现有设置和 capability 结果派生状态。
- 不引入新的状态管理库。
- 不把“存在 Key”当成“连接成功”。
- 不把 capability 加载失败当成默认可用。

### 1.2 首次设置向导

采用 App 内条件渲染，不引入新的路由系统。设置中保存：

- onboardingCompletedAt
- lastReadinessCheckAt
- lastReadinessResult

向导步骤：

1. 产品边界与隐私说明。
2. 模型供应商选择、Key 输入和真实连接测试。
3. STT 供应商选择、Key 输入和真实连接测试。
4. 麦克风、系统音频和权限测试。
5. 60 秒测试会话。

简历导入作为推荐步骤，不阻塞首次试用。

首期保留当前 Deepgram 默认 STT，不在激活阶段同时引入平台差异更大的默认方案。向导必须明确说明模型和 STT 可能需要两把不同的 Key；只完成模型配置时，状态仍为 unconfigured。后续是否更换默认 STT，由真实测试成功率、语言覆盖和用户成本决定。

### 1.3 就地修复

- 缺模型 Key：直达 Settings 的 AI Provider 页签。
- 缺 STT Key：直达 Speech to Text 页签。
- 麦克风被拒绝：显示系统设置入口和重试。
- 系统音频不可用：显示平台条件和替代方案。
- 供应商请求失败：将错误归类为认证、限额、网络或服务错误。
- 从 Dashboard 或 Copilot 进入设置时保存来源；修复成功后提供“返回测试”或“返回 Copilot”，不让用户重新寻找入口。
- Copilot 内的能力错误在发生位置显示修复和重试，不只依赖 Settings 中的 alert。

### 1.4 默认音频策略

- 实时 Copilot：系统音频默认开启，麦克风默认关闭。
- Mock：麦克风默认开启。
- 用户主动选择双路捕获后保存偏好。

此项用于降低回声和重复说话人，不改变用户显式选择。

### 自动验收

- 无 Key、Key 无效、STT 缺失、权限拒绝、capability 加载失败各有一个聚焦回归检查。
- 只配置模型 Key 而未配置 STT 时，不得显示 ready 或绿色状态。
- readiness 只有在所有核心条件通过时为 ready。
- 首次向导完成后重启不重复出现。
- 修改当前供应商或清除 Key 后，readiness 立即失效。
- npm run build 通过。

### 运行验收

在干净本地数据下分别验证 macOS 和 Windows：

- 首次启动到向导。
- 无效 Key 的可理解错误。
- 有效 Key 的连接测试。
- 系统音频和麦克风检查。
- 首条真实建议出现。
- 重启后状态恢复。

阶段出口指标：

- 至少 60% 的合格下载进入设置向导。
- 至少 50% 的向导用户完成模型和 STT 测试。
- 至少 40% 的合格下载完成音频测试。
- 首次建议中位时间不超过 15 分钟。

这些数字是首轮实验阈值，不是行业基准。

### 阶段 2：统一 Interview Profile 与核心上下文

时间：第 2 至 3 周  
目标：让 Copilot、Mock 和 Resume 围绕同一目标岗位工作。  
优先级：P0

### 2.1 扩展现有简历工作区

增加：

- targetRole：目标岗位，必填建议但不阻塞测试。
- targetCompany：目标公司，可选。
- profileUpdatedAt：用于判断分析是否过期。

不新增独立 Profile 数据库表，先维持一个当前 Profile。出现用户明确需要同时管理多个求职目标时，再设计多 Profile。

### 2.2 上下文优先级

Copilot 和 Mock 使用同一规则：

1. 若优化简历存在且未因原始简历或 JD 修改而过期，使用优化简历。
2. 否则使用原始简历。
3. 始终加入 targetRole。
4. 有 targetCompany 时加入公司。
5. 有 jobDescription 时加入职位描述。
6. 保留最近对话上下文。

代码落点：

- [src/pages/ResumeOptimizer.tsx](../src/pages/ResumeOptimizer.tsx)
- [src/pages/MockInterview.tsx](../src/pages/MockInterview.tsx)
- [src/lib/copilotSession.ts](../src/lib/copilotSession.ts)
- 现有简历工作区存储模块

### 2.3 Dashboard 面试卡

显示：

- 当前目标岗位与公司。
- Profile 完整度。
- 模型、STT、音频状态。
- 60 秒测试入口。
- 开始 Copilot 主按钮。
- 3 题 Mock 次按钮。

Dashboard 不再把 Copilot、Mock、Resume 三张卡表现为同等核心动作。

### 2.4 会话身份

开始 Copilot 前生成 session identity：

- mode：copilot 或 mock。
- targetRole。
- targetCompany。
- startedAt。
- profileVersion 或 profileUpdatedAt。
- isTestSession。

停止后标题优先使用“公司 · 岗位 · 日期”，缺失时再使用转写摘要，不再固定写“Stealth Copilot”。

### 自动验收

- 修改目标岗位后，Copilot 和 Mock 都读取新值。
- 有效优化简历优先于原始简历。
- 优化分析过期时自动回退原始简历。
- 测试会话带 isTestSession，不进入正式统计。
- 现有旧数据缺少新字段时仍可读取。
- npm run verify:copilot 与 npm run build 通过。

### 运行验收

- 使用同一 Profile 完成一次 Mock 和一次 Copilot。
- 检查两者提示包含相同岗位、公司、JD 和正确简历版本。
- 检查历史标题和详情正确。

阶段出口指标：

- 进入 Copilot 的用户中，至少 70% 已有 targetRole。
- 使用 Profile 的会话“建议有帮助”比例高于无 Profile 会话。
- Profile 建立后到首次 Copilot 的中位步骤不超过 3 个主要动作。

### 阶段 3：会话可靠性、数据纪律与复盘价值

时间：第 3 至 4 周  
目标：保护真实面试记录，并把已生成反馈转化为留存价值。  
优先级：P0

### 3.1 Clear 数据保护

- 有任何转写或建议时，Clear 必须二次确认。
- 明确说明 Clear 会删除当前未归档内容。
- 正在停止或保存时禁用 Clear。
- 若用户只想清空当前建议，提供不影响 transcript 的最小动作；没有明确需求前不增加复杂撤销系统。

### 3.2 有效会话分类

复用现有会话数据，不新增模型调用。会话分为：

- test：由 60 秒测试入口创建。
- noise：无有效面试官问题或有效内容不足。
- valid：至少存在一个有效面试官问题和一条建议，或用户手动确认为有效。
- incomplete：意外终止但有可恢复内容。

只有 valid 进入 Dashboard 面试次数和平均分。test、noise 和 incomplete 保留在历史的辅助筛选中，但不污染核心指标。

阈值必须集中在一个现有逻辑模块中，避免页面各自判断。

### 3.3 最小会话恢复

首期只保存恢复所需最小快照：

- session identity。
- transcript messages。
- suggestion messages。
- startedAt。
- current state。

触发：

- 每次稳定转写或建议完成后节流保存。
- 正常 stop 后转为正式历史并清除快照。
- App 启动发现快照时询问恢复或丢弃。

不在首期实现完整音频断点续传。音频仍按当前录制机制保存；若进程崩溃导致音频不完整，应清楚标记。

### 3.4 History 复盘

展示已有 detailsJson 中的：

- summary。
- strengths。
- improvements。
- overall score。
- 下一次建议动作。

同时增加：

- 空态开始 Copilot 和开始 Mock CTA。
- 会话类型标签。
- 测试/噪声标记。
- 有效性手动纠正。

单条重命名和删除排到 P1；只有用户研究证明历史管理困难时再加入批量标签。
在单条删除和重命名完成前，将“View and manage”一类承诺改为与实际能力一致的“查看、复盘和导出”。

### 3.5 Dashboard 数据口径

- Total Interviews：valid 会话数。
- Average Score：有评分的 valid 会话平均。
- Practice Time：valid Copilot + valid Mock 的实际时长。
- Recent Activity：展示所有有意义的会话，但明确类型。

### 自动验收

- Clear 确认逻辑覆盖空会话、有内容会话和保存中会话。
- test/noise 不计入 Dashboard。
- valid 会话仍正常计分。
- detailsJson 旧数据缺失或格式异常时安全降级。
- 录音保存成功但评分失败、评分成功但录音失败等部分归档状态均可读取，并给出准确提示。
- 崩溃快照可恢复，正常停止后不重复恢复。
- npm run verify:copilot、相关前端验证脚本和 npm run build 通过。
- cargo test --manifest-path src-tauri/Cargo.toml 连续运行至少两次，观察已知音频 sidecar 间歇问题。

### 运行验收

- 完成一次测试会话、噪声会话、正常会话和强制退出恢复。
- 核对 Dashboard 只统计正常会话。
- 核对 History 展示强项、改进和摘要。
- 核对 Clear 无法误删未保存记录。

阶段出口指标：

- 90% 以上的有效会话成功归档。
- History 详情打开率达到有效会话用户的 35%。
- 14 天内完成第二次有效会话的用户达到首批激活用户的 40%。

### 阶段 4：公开分发、安全与信任门槛

时间：第 2 至 6 周，可与阶段 2、3 并行  
目标：让外部用户可以安全下载、安装和更新。  
优先级：P0，未完成前禁止付费推广

### 4.1 统一发布源

选择一个公开可访问的正式发布端点，并保证：

- 下载页、应用 updater、CI 发布目标一致。
- latest.json、安装包、签名文件和版本号一致。
- 匿名用户可访问 updater URL。
- App 当前版本能升级到下一测试版本。
- 私有源码仓库和公开二进制分发可分离，但用户下载不依赖 GitHub 登录。

不同时维护两个不同版本的 updater 仓库。

### 4.2 签名与公证

macOS：

- Developer ID Application 签名。
- Apple notarization。
- staple 验证。
- 新用户机器 Gatekeeper 安装测试。

Windows：

- Authenticode 签名。
- SmartScreen 新装测试。
- 卸载与升级保留数据测试。

### 4.3 API Key 存储

用系统安全存储替代静态 seed XOR：

- macOS Keychain。
- Windows Credential Manager。

首期只迁移模型和 STT API Key。普通偏好继续使用现有本地设置。

迁移要求：

- 读取旧值后写入系统安全存储。
- 成功后删除旧值。
- 迁移失败时不删除旧值，并提示用户重新输入。
- 清除所有数据时同时清除安全存储。

### 4.4 CSP 与能力边界

- 为 Tauri WebView 配置最小 CSP。
- 只允许当前运行需要的连接目标。
- 检查 Tauri capabilities、Info.plist 和 entitlements.plist 一致。
- 不扩大 shell、文件系统或网络权限。

### 4.5 信任文档

公开：

- Privacy Policy。
- Terms of Use。
- Recording Consent Guide。
- AI Provider Data Flow。
- Supported Platforms and Known Limitations。
- Refund Policy。

核心披露：

- Rabbit 不经营第一方面试内容后端。
- 请求会直接发送给用户选择的第三方供应商。
- 用户负责第三方 API 成本和供应商条款。
- 用户应遵守面试方规则并取得必要录音同意。
- 屏幕保护能力受操作系统和会议软件影响，不承诺绝对不可见。

### 验收

- 全新 macOS 和 Windows 用户可匿名下载。
- 安装过程无未签名阻断。
- 自动更新从正式版本升级到候选版本成功。
- Key 不再以可逆静态 seed 形式保存在普通设置。
- 删除本地数据后 Key、简历、历史、录音和恢复快照均被清除。
- 隐私文案与真实数据流逐项一致。

阶段出口条件：

- 公开下载、签名、公证、updater、隐私政策和条款全部通过，才能进入付费试点。

### 阶段 5：最小商业化闭环

时间：第 6 至 8 周  
目标：用最少工程验证用户是否愿意为实时 Copilot 付费。  
优先级：P1

### 5.1 权益模型

只定义一个付费权益：

- copilotSeasonPassExpiresAt

免费用户：

- Copilot 累计体验 10 分钟。
- Resume、Mock 和 History 保持可用。

付费用户：

- 在有效期内不受 Rabbit 的 Copilot 时长限制。
- 第三方 API 仍由用户承担。

不按生成次数、建议条数或 Mock 次数建复杂额度。

### 5.2 本地签名许可证

首批 20 至 50 位试点用户使用：

1. 外部现成收款页面完成支付。
2. 运营生成包含到期时间和许可证 ID 的签名 license。
3. App 只内置公钥并验证签名。
4. 本地保存激活状态。

要求：

- 私钥不进入仓库和客户端。
- 时钟回拨有最小检测和明确错误。
- 许可证损坏时不影响本地数据。
- 允许人工补发。
- 首批接受清理本地数据可能重置免费试用的漏洞；出现真实滥用再考虑账号或设备绑定。

### 5.3 付费墙

触发：

- 免费体验剩余 2 分钟时温和提醒。
- 体验耗尽后停止新建议，不中断转写和会话保存。
- 面试前 readiness 页面显示剩余时间。

付费墙内容：

- 90 天有效期。
- 一次性价格。
- 不包含第三方 API 费用。
- 支持的平台和供应商。
- 退款政策。
- 激活方式。

禁止在真实面试进行中突然遮挡整个界面。

### 5.4 最小隐私事件

首期事件只用于漏斗，不上传内容。

| 事件 | 允许字段 |
|---|---|
| app_first_open | appVersion、platform、locale |
| onboarding_started | appVersion、platform |
| provider_test_result | providerType、success、errorCategory |
| stt_test_result | providerType、success、errorCategory |
| audio_test_result | sourceType、success、errorCategory |
| first_suggestion_shown | elapsedBucket、providerType |
| suggestion_feedback | helpful |
| valid_session_completed | mode、durationBucket、suggestionCountBucket |
| history_detail_opened | mode、ageBucket |
| paywall_viewed | trigger、remainingTimeBucket |
| checkout_opened | planId |
| license_activated | planId、success、errorCategory |
| app_updated | fromVersion、toVersion、success |

永不采集：

- 音频。
- 转写正文。
- Copilot 建议正文。
- 简历。
- 职位描述。
- 公司名称。
- 岗位名称。
- API Key。
- 本地文件路径。

若不愿接入远端 analytics，首批可先导出匿名本地诊断汇总，由用户主动发送。营销规模扩大前再决定是否引入事件服务。

### 验收

- 免费体验时间在重启后保持一致。
- 体验耗尽不丢失正在进行的 transcript。
- 有效 license 在离线状态下可验证。
- 过期、篡改、损坏和错误版本 license 有明确状态。
- 激活失败不覆盖原有效 license。
- 埋点 payload 自动检查禁止敏感字段。
- 购买和激活说明能由一名未参与开发的测试者独立完成。

首轮商业验证目标：

> 100 个合格下载 → 40 个音频测试成功 → 25 个首次建议 → 10 个用户在 14 天内完成第二次有效会话 → 5 个季卡购买。

这是一组 go/no-go 实验门槛。若激活未达标，先修产品；若激活达标但购买低，先访谈价值和价格，不立即增加套餐。

### 阶段 7：留存与增长实验

时间：第 9 至 12 周  
目标：验证重复使用，再决定是否做裂变和规模化投放。  
优先级：P2

### 7.1 留存循环

产品内循环：

Interview Profile → 60 秒测试或 Mock → 实时 Copilot → History 复盘 → 下一次练习建议 → 更新 Profile

首期提醒只做本地提醒：

- 距上次有效会话 7 天且有活跃求职季时，提示进行 3 题热身。
- 新版本可用时，显示可验证的更新说明。
- 不发送未经用户同意的邮件。

### 7.2 优先实验

| 实验 | 假设 | 成功指标 | 决策 |
|---|---|---|---|
| 60 秒音频测试 | 先证明能听到，可降低首次失败 | 测试完成到首次建议转化提升 20% | 保留或改进步骤 |
| Profile 完整度 | 岗位上下文提高建议可用性 | helpful 比例提升 15% | 保留完整度提示 |
| 3 题热身 | 面试前短 Mock 提高实战复用 | 14 日第二次有效使用提升 10% | 保留或移除入口 |
| 10 分钟体验 | 足够体验价值且不延迟购买 | 体验用户购买率达到 15% | 调整体验长度 |
| ¥199 季卡 | 符合 1 至 3 个月求职周期 | 首批激活用户购买率达到 20% | 保留或进行价格访谈 |
| 真实复盘卡 | 反馈展示促进回访 | History 打开率提升 20% | 扩展下一步动作 |

每次只运行少量有独立判断价值的实验。样本不足时，不因短期波动引入新套餐。

### 7.3 Referral 启动门槛

只有同时满足以下条件才做推荐机制：

- 14 日第二次有效使用率至少 40%。
- 至少 50 位付费用户。
- 退款和严重投诉率可接受。
- 激活漏斗已稳定两个版本。

最小 referral 方案：

- 推荐人和新用户各获得 7 天季卡延长。
- 一个本地许可证 ID 对应有限次数。
- 不做多级分销、现金返佣或创作者后台。

如果门槛未达到，继续优化激活和复盘，不做裂变。

## 8. 定价策略

### 8.1 为什么选择 90 天季卡

- 求职需求天然集中在一段时间内。
- 用户不愿为了偶发面试长期订阅。
- BYOK 意味着 Rabbit 不承担主要推理成本，不需要用高额订阅覆盖模型费用。
- 单一方案易解释、易运营、易测试。
- ¥199 / $39 明显低于多数托管推理竞品，但不把产品定位成免费工具。

### 8.2 竞品参照

截至 2026-08-26 的官方公开信息：

- [Final Round AI](https://www.finalroundai.com/blog/what-is-final-round-ai)：约 $90/月、$180/季度、$300/年，并提供 10 分钟试用。
- [LastRound AI](https://lastroundai.com/pricing)：$19、$49、$99 月档，使用 credits。
- [Beyz AI](https://beyz.ai/)：公开月档约 $49.99。
- [Interview Coder](https://www.interviewcoder.co/)：约 $299/月、$799 终身。
- [LockedIn AI](https://docs.lockedinai.com/docs/billing/plans-credits-and-promos)：按 credits 或无限档，提供新用户试用。

Rabbit 不应照搬托管模型产品的 credits，因为当前第三方推理成本由用户承担。若未来提供 Rabbit 云模型，再单独建立按分钟或 credits 的可选方案。

### 8.3 价格验证方法

首批不要做复杂 A/B 测试，采用连续访谈：

1. 记录用户看到价格前的激活和使用情况。
2. 询问未购买用户：价值不足、价格高、支付不便、信任不足还是求职需求不强。
3. 询问购买用户：主要购买理由和替代工具。
4. 只有出现至少 20 条同类证据，才调整价格或权益。

优先修正顺序：

1. 产品是否成功。
2. 用户是否信任。
3. 权益是否清楚。
4. 支付和激活是否顺畅。
5. 最后才是价格。

## 12. 验证矩阵

### 12.1 静态与自动化

每个阶段至少执行：

- npm run build
- npm run verify:copilot
- 相关已存在的前端验证脚本
- cargo test --manifest-path src-tauri/Cargo.toml
- cargo fmt --manifest-path src-tauri/Cargo.toml --check，仅针对实际触及的 Rust 范围评估现有漂移

新增非平凡逻辑必须留下一个最小回归检查。优先扩展现有 scripts 验证工具和现有 Rust 模块测试，不为单个功能引入新测试框架。

### 12.2 桌面运行验证

macOS：

- 麦克风权限。
- ScreenCaptureKit 系统音频。
- 系统安全存储。
- 屏幕共享保护。
- 签名、公证、安装、升级。

Windows：

- WASAPI 系统音频。
- 麦克风权限。
- Credential Manager。
- 屏幕共享保护。
- 签名、安装、升级、卸载。

两端都要验证：

- 干净首次启动。
- 无效和有效供应商 Key。
- 网络中断和恢复。
- 10 分钟试用边界。
- 正常停止、强退恢复和历史复盘。
- 清除全部本地数据。
- 一次完整真实设备链路：开始捕获 → 系统音频与麦克风双路转写 → AI 建议 → 停止 → 录音、评分和复盘进入 History。
- 权限拒绝、设备为空、供应商无效、断网、部分归档失败、无录音、无评分和损坏 detailsJson。
- 键盘全流程、焦点恢复、tab/tablist 语义、图标按钮名称、动态错误播报、缩放和基本对比度。

源码检查和自动化测试不能替代上述真实设备流程。

### 12.3 发布候选门槛

候选版本必须满足：

- 构建和聚焦验证全部通过。
- Rust 全量测试稳定；已知音频 sidecar 间歇失败需要得到修复或有明确阻断决定。
- 两个平台至少各一台干净机器完成安装和核心流程。
- updater 匿名可访问并完成一次真实升级。
- 隐私政策与实际供应商调用逐项核对。
- 支付、许可证补发和退款流程由非开发人员演练。

## 13. 风险与处理

| 风险 | 影响 | 处理 |
|---|---|---|
| BYOK 配置过于复杂 | 首次激活低 | 向导、真实连接测试、供应商推荐和 60 秒测试 |
| 第三方供应商不稳定 | 实时建议失败 | 状态分类、就地重试、保留 transcript、支持多供应商 |
| 系统音频平台差异 | 核心功能不可用 | 平台专属检查、已知限制、干净机器验收 |
| 双路音频回声 | 转写和说话人污染 | 实战默认系统音频，麦克风显式开启 |
| 用户误解隐私 | 信任和法律风险 | 公开数据流图，避免“完全本地”绝对表述 |
| 面试规则不允许辅助 | 品牌和合规风险 | 首次向导、网站和 Terms 持续提醒用户确认规则 |
| 本地 license 被绕过 | 收入损失 | 首批接受有限漏洞，用真实滥用决定是否升级 |
| 过早做账号后端 | 延迟商业验证 | 首批使用离线签名许可证 |
| 过早做复杂套餐 | 用户困惑 | 只保留免费 + 季卡 |
| 过早裂变 | 带来低质量用户 | 达到留存和付费门槛后再做 |
| 指标采集侵犯隐私 | 破坏核心差异化 | 只采集行为元数据，自动禁止内容字段 |
| 未签名安装包 | 下载转化低 | 签名、公证作为收费前硬门槛 |

## 14. 明确不做

首个 12 周周期内不做：

- 产品账号系统。
- 自营模型代理或云转写。
- 多用户、团队和企业后台。
- 手机 App。
- 自动投递和职位搜索。
- 多 Interview Profile 管理。
- 复杂标签、文件夹和知识库。
- 多级订阅、credits 和终身版。
- 现金返佣或创作者后台。
- 大规模付费广告。
- 全量重做 UI 或导航。
- 新状态管理框架、路由框架或测试框架。
- 为“可能以后需要”建立抽象层。

这些能力只有在用户证据或运营成本达到明确阈值时再立项。

## 15. Go / No-Go 决策

### 15.1 可以公开收费

必须同时满足：

- 匿名下载、签名、公证和 updater 工作。
- 首次设置到第一条建议可由外部测试者独立完成。
- API Key 使用系统安全存储。
- Privacy、Terms、Refund 和数据流说明上线。
- 有效会话归档和恢复通过运行验证。
- 免费体验和 license 在离线状态可靠。

### 15.2 可以扩大营销

必须同时满足：

- 100 个合格下载中至少 25 个首次建议。
- 至少 10 个用户在 14 天内完成第二次有效会话。
- 至少 5 个求职季卡购买。
- 没有未解决的安装、数据丢失或密钥安全 P0 问题。
- 用户能准确复述 Rabbit 的数据流和第三方 API 成本。

### 15.3 应暂停扩量

任一情况发生时暂停：

- 首次建议转化低于 20%。
- 有效会话归档成功率低于 90%。
- 安装或 updater 大面积失败。
- 用户频繁误解隐私承诺。
- 用户认为建议质量不足，但 Profile 已完整且链路正常。
- 退款主要原因是产品能力与营销承诺不一致。

暂停后只修复最大的漏斗断点，不通过增加功能掩盖问题。

## 16. 完成定义

本轮优化完成，不是指所有任务都已编码，而是产品达到以下可验证状态：

> 一位此前没使用过 OnCue 的目标用户，可以从公开渠道下载签名应用，在 15 分钟内完成模型、STT 和音频配置，建立目标岗位上下文，获得第一条有用建议，完成并恢复一场真实会话，在 History 中看到具体改进项，清楚理解数据会发送给哪些第三方，并能用 ¥199 / $39 激活 90 天求职季卡。

如果这一条链路不能稳定复现，营销、Referral、更多套餐和企业功能都应继续后置。
