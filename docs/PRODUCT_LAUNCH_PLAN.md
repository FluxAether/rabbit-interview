# 求职产品落地计划

> 依据：当前 App 实测（仪表盘 / 隐形助手 / 模拟面试 / 简历 / 设置 / 历史）与即答侠公开定价。
> 目标：把 OnCue 从本地面试工具收成能卖的求职产品。先让一场面试干净可复盘，再卖求职季卡，不卖 Token。

## 0. 产品定义

一句话：**面试内容不离开这台电脑。系统音频听面试官，浮窗只给你看，Key 是你自己的。**

用户买的不是模型，是这 90 天里能反复用的三件事：

1. 对着目标岗位改简历
2. 用同一份 JD 做模拟面试
3. 在真实会议里拿结构化提示，结束后能复盘

非目标：题库商城、积分、手机同步、截图刷题、云端账号。这些是即答侠的量产路径，会把产品拖进账单和客服，而不是差异化。

当前约束保持不变：

- 无第一方后端。面试内容、简历、Key、录音继续留在本地 SQLite / 应用数据目录
- MIT 源码可以继续开；收费的是公证安装包、自动更新和支持
- 营销和产品文案不得承诺“完全隐身 / 面试官无感”

## 1. 当前断点（必须先修）

| 断点 | 现状 | 后果 |
|---|---|---|
| Copilot 没有会话身份 | `CopilotStartConfig` 只有音频开关；归档把第一句转写写入 `role`，`company` 写死 `Stealth Copilot` | 仪表盘和历史被闲聊、广告、小说污染 |
| 停止即评分 | `archiveSession()` 只要有麦克风问答对就会调 `scoreCopilotSession()` | 家庭闲聊变成 8/100、42 分 |
| 模拟面试可空跑 | `startInterview()` 只校验职位；简历/JD 0 字也能开始 | 历史里模拟面试 0 条，用户跳过主路径 |
| 工作区没有“当前岗位” | 简历页、模拟面试、Copilot 各读各的文本 | 三件套无法讲成一条求职故事 |
| 首次使用是设置页 | 仪表盘 onboarding 第一步是“去填 API Key” | 新用户还没听到系统音频，就已经走丢 |
| 分发不是产品 | 仓库私有，GitHub 最新安装包 `v0.7.0`，应用 `0.11.1`；无落地页、无付费墙 | 功能再完整也卖不出去 |

## 2. 原则

- **一场面试一个会话。** 没有职位，不允许开始捕获；没有合格面试证据，不进“辅助面试次数”，不打分。
- **一个目标岗位。** 一份简历 + 一份 JD，同时供给简历优化、模拟面试、隐形助手。
- **说话人纪律。** 系统音频 = 面试官，麦克风 = 我。面试官没提问，不生成长答案。
- **状态说实话。** 屏幕捕获保护、Key、音频测试不过，就拦在开始前，不在面试中角落提示。
- **先卖季卡，不卖积分。** 软件能力收费，Token 用户自付。
- **最小 diff。** 沿用现有 session host、`interviews` 表、`resume_workspace`、`verify:copilot`，不另起后端和状态层。

## 3. 目标工作流

```text
首次打开
  → 向导：语言 / 一个 LLM Key / 转写 / 10 秒系统音频测试 / 保护状态
  → 仪表盘只显示合格面试

当前岗位工作区
  → 导入简历 + 粘贴 JD
  → 可选：优化并导出
  → 模拟面试（无简历/JD 则警告或拦截）
  → 实战 Copilot（开始前填职位/公司，沿用当前 JD）
  → 停止后归档：公司 · 职位 · 日期；合格才计分
```

## 4. 分阶段实施

### 阶段 0：会话身份与归档纪律（P0，本周）

**用户可见结果**

- 点“开始捕获”前必须填职位，公司可选
- 停止后历史标题是 `公司 · 职位`，不是第一句转写
- 闲聊/广告会话可进原始记录，但不进仪表盘“辅助面试次数”，也不显示分数

**改哪里**

1. 扩展 `CopilotStartConfig`（`src/lib/copilotSession.ts`）增加 `role`、`company`。快捷键 `toggle` 若没有配置，先弹出主页面/浮窗的会话条，不要直接开麦。
2. `CopilotSnapshot` 增加当前会话 `role` / `company`，停止后带进归档。
3. 改 `createCopilotInterviewRecord()`（`src/lib/copilotArchive.ts`）：
   - `role` = 用户填写的职位
   - `company` = 用户填写的公司；空则 `未指定`
   - 标题不再用 `generateCopilotSessionTitle(messages)`
   - 第一句转写可写入 `detailsJson.preview`，仅详情页展示
4. 给归档加合格门槛，做成 `copilotArchive.ts` 或 `copilotScoring.ts` 的纯函数：

   合格面试 = 至少 1 个面试官问题 **且** 至少 1 个达到 `isMinimumVoiceAnswer()` 的麦克风回答。

   - 不合格：`score = null`，`detailsJson.quality = 'noise'`，不调用 LLM 评分
   - 合格：才调用现有 `scoreCopilotSession()`
5. `computeDashboardStats()` 只统计 `mode = 'copilot'` 且 `quality != 'noise'` 的记录；分数只取有 `score` 的合格会话。仪表盘“最近活动”同样过滤噪音。
6. 历史列表（`src/pages/History.tsx`）：主标题 `{company} · {role}`；搜索继续走现有 `role`/`company` LIKE。按钮文案不要重复整段标题。
7. Copilot 页开始区：职位输入、公司输入、当前 JD 摘要（只读，来自工作区）、保护状态。保护未启用时，“分离浮窗”前给出说明，不阻断本机练习。

**验证**

- 扩展 `scripts/verify-copilot.mjs`：
  - 有职位的归档标题不是转写原文
  - 只有麦克风闲聊 / 只有系统音频小说 → `score === null` 且 `quality === 'noise'`
  - 1 个面试官问题 + 1 个足够长的麦克风回答 → 才会走到评分输入
- 扩展 `scripts/verify-dashboard-stats.mjs`：噪音记录不计入 `interviewCount`
- 手工：开始 → 说两句家常 → 停止 → 历史有记录、仪表盘次数不增加

**完成定义**

- 现有脏历史可以保留，不做迁移；新会话不再污染仪表盘
- `npm run verify:copilot` 与 dashboard stats 校验通过

### 阶段 1：首次设置向导（P0，紧接阶段 0）

**用户可见结果**

第一次打开不是设置页，而是 4 步向导。过完之前，仪表盘不假装“欢迎回来”。

**步骤**

1. 语言（沿用现有 `settings.language`）
2. 选一个 LLM 供应商，贴 Key，点现有“测试连通性”
3. 选转写：Deepgram Key / Gemini 复用 / Apple 本地（不可用则禁用并写原因）
4. 10 秒系统音频测试：播放本机声音，确认出现转写；麦克风可选

通过后写入 settings：`onboardingCompleted: true`。失败时停在当前步，不要进主界面装成已就绪。

侧栏 `AI ENGINE` 绿灯改成真实状态：LLM Key 已测通 **且** STT 已测通。缺一显示“未就绪”，点击回到缺的那一步。

**改哪里**

- `AppSettings` 增加 `onboardingCompleted`、可选 `lastLlmTestAt` / `lastSttTestAt`（`src/lib/settingsStore.ts`）
- 新组件 `src/components/SetupWizard.tsx`，由 `App.tsx` 在 `onboardingCompleted !== true` 时全屏覆盖；不要新路由系统
- 复用 Settings 里已有的连通性测试，不要复制一套 Key 表单
- 删除 Groq/OpenAI 输入框里的 `GROQ_API_KEY` 占位符，空就空
- 仪表盘 onboarding 文案改成求职步骤：当前岗位 → 模拟面试 → 实战助手；Key 只在未就绪时出现

**验证**

- 清空 settings 后启动，必进向导
- 向导未完成不能开始 Copilot / 模拟面试
- Apple STT 不可用时不能被选成“使用中”还假装通过
- `npm run build`；补最小 wizard 状态校验（有/无 `onboardingCompleted` 的渲染分支）

**完成定义**

新用户 3 分钟内能听到系统音频被转写，或明确知道缺权限/缺 Key。

### 阶段 2：当前岗位工作区（P1）

**用户可见结果**

App 顶部或仪表盘有“当前岗位：公司 · 职位”。简历、模拟面试、Copilot 都吃同一份 JD 和简历。

**改哪里**

工作区已有 `resume_workspace` JSON。不要新表，只补字段到现有 workspace：

- `targetRole`
- `targetCompany`
- `status`: `empty | ready | optimized`
- 继续用现有 `original` / `optimized` / `jobDescription`

读取优先级：Copilot 和模拟面试默认 `resumeOptimized || resumeOriginal`，JD 默认工作区 JD。用户仍可在模拟面试页覆盖，但空启动时自动同步，不再靠“一键同步”小按钮。

简历页：

- 没简历时主按钮保持禁用，文案改成“先上传简历”
- 有简历无 JD 时按钮是“通用优化”，有 JD 时是“按 JD 优化”
- 优化完成后，仪表盘当前岗位变为 ready

模拟面试：

- 无职位：继续拦截（已有）
- 无简历且无 JD：主按钮变为“先同步当前岗位”，或二次确认“将进行通用模拟，答案无法贴合你的经历”
- 有工作区内容时进入 setup 即填充，去掉必须手点同步

Copilot `buildContext()` 已读取简历/JD；改为优先优化稿，并带上 `targetRole` / `targetCompany`。

**验证**

- 简历页导入 + 粘贴 JD 后，打开模拟面试，输入框已有内容
- Copilot 开始条预填同一职位/公司
- 扩展 `verify:resume`：workspace 字段读写；扩展 mock 校验：空上下文不能无提示开跑

### 阶段 3：说话人纪律与保护前置（P1）

**用户可见结果**

家庭闲聊不再触发长篇“核心提示”。分离浮窗前能看见保护是否生效。

**改哪里**

1. 默认捕获：实战模式只开系统音频；“同时捕获麦克风”改为高级选项，默认关。练习/复盘需要自己的回答时再开。
2. `flushPendingInterviewerAnswer()` 增加门槛，复用 `isCompleteInterviewPrompt()` / `isMinimumVoiceAnswer()`：过短、无问句、明显非面试先用现有 incomplete/complete 规则拦住，不做分类模型。
3. 麦克风文本默认只进会话，不触发 `answer()`。追问继续走现有 follow-up 输入框。
4. 分离浮窗：`protection_applied !== true` 时先说明限制（焦点/进程/摄像头），用户确认后再 detach。主面板状态条保持现有诚实文案。
5. 文案：中英徽章统一。仪表盘去掉 `AI SIMULATION` / `ATS TARGETING` 英文标签，或改成中文。

**验证**

- 系统音频转入“今天吃什么” → 不生成建议
- 系统音频转入完整面试问题 → 生成建议
- 扩展 `verify-copilot.mjs` 的 turn detector / answer 触发断言
- 手工：保护关闭时 detach 有确认

---

### 阶段 4：把模拟面试做成主路径（P1）

**用户可见结果**

仪表盘主 CTA 从“启动隐形助手”改为“先模拟这场面试”。历史里开始出现 mock 记录。

**改哪里**

- 仪表盘三张卡排序：当前岗位 → 模拟面试（主按钮）→ 隐形助手（次按钮）
- 模拟面试结束后，报告页增加“用同一岗位开启实战助手”
- 历史默认 Tab：若 mock 为 0 且 copilot 多为噪音，空状态引导去模拟，而不是展示垃圾 Copilot 列表
- 分数口径：仪表盘平均分只取 mock 报告分；Copilot 分可在详情显示，不进总平均，避免 8/100 这种不可解释数字

**验证**

- 走完一次 5 题文本模拟，历史 mock 计数 +1
- `npm run verify:mock`
- 仪表盘平均分在只有噪音 Copilot 时显示 `-`

### 阶段 5：可卖的外壳（P1/P2）

可与 2–4 并行准备，但产品纪律完成后再对外下载。

**用户可见结果**

有一个能下载、能更新、能收款的求职季卡。没有账号体系也可以先卖。

**定价（冻结到首发）**

| 方案 | 价格 | 权限 |
|---|---|---|
| 免费 | ¥0 | 向导 + 模拟 3 次 + 简历 1 次 + Copilot 试听 20 分钟 |
| 月卡 | ¥79 / 30 天 | 无限本地会话 |
| 求职季卡 | ¥199 / 90 天 | **主推**。无限本地会话、隐身浮窗、历史导出 |
| 终身 | ¥499 | BYOK 用户，一次买断客户端能力 |

不包含 Token。专业版也不靠“允许自带 Key”制造价差——Key 始终是用户的。

**怎么收，不自建账户系统**

最小方案：

1. 落地页（独立站点，不进 Tauri 包）下载当前公证安装包
2. 支付用现成收款（Lemon Squeezy / Paddle / 国内的微信+兑换码，三选一，先做一个市场）
3. App 内 `Settings → 许可证`：粘贴许可证密钥，本地校验签名
4. 免费额度记在本地 settings；清数据可重置，接受这个漏洞，首发不做设备指纹

许可证只锁：Copilot 超过试听时长、模拟超过 3 次、简历超过 1 次。向导、历史回看、设置始终可用。

**分发**

- 源码 release 与安装包版本对齐到同一个 `vX.Y.Z`，结束 `v0.7.0` 最新、应用 `0.11.1` 的分裂
- macOS Developer ID + 公证；Windows 至少能过 SmartScreen 的说明。做不到就在下载页写明，不要装成商店应用
- 落地页一屏：那句定位、30 秒演示、隐私三点、下载、季卡。条款写清：仅在面试规则允许辅助工具时使用

**营销，产品能演示后再做**

1. 30 秒：会议在响，浮窗出要点，任务栏无异常；结尾加规则允许声明
2. 隐私向：为什么 BYOK、录音在哪、没有账号
3. 准备向：同一份 JD，先简历，再模拟，再实战

渠道：小红书（求职准备）、B 站（系统音频原理）、V2EX/即刻（BYOK）。不承诺 Offer 返现。

**验证**

- 无许可证：第 4 次模拟被拦，并给出季卡说明
- 有许可证：不拦截
- 安装包校验：现有 `verify-release-assets.mjs` + 版本号与 `package.json` / `tauri.conf.json` 一致
- 本阶段不把收款后台做进 `src-tauri`

## 5. 明确不做

- 积分、按次云端 Copilot、自营模型网关
- 为脏历史做清洗迁移
- 截图解题 / 找 Bug / 手机同步 / 窗口名伪装
- 新的云端账号、同步、多设备登录
- 为了营销改保护文案，改口成“完全不可见”

这些等阶段 0–4 的完成定义都过了再单独立项。

## 6. 建议工期与依赖

```text
Week 1: 阶段 0 会话身份 + 阶段 1 向导骨架
Week 2: 阶段 1 音频测试打通 + 阶段 3 说话人纪律
Week 3: 阶段 2 工作区串联 + 阶段 4 仪表盘主路径
Week 4: 阶段 5 落地页/许可证最小环 + 对齐发布版本
```

依赖：阶段 5 对外下载，必须等阶段 0 和 1 完成。否则新用户下载后仍会录一堆垃圾会话。

人员假设：1 人全职可按上面四周走。许可证支付和公证可另开线，但不替换产品纪律。

## 7. 验证基线

每个阶段结束至少跑：

- `npm run build`
- `npm run verify:copilot`
- 触及模拟时 `npm run verify:mock`
- 触及简历时 `npm run verify:resume`
- 触及仪表盘时 `node scripts/verify-dashboard-stats.mjs`

手工必测：

- 新用户向导 → 系统音频测试成功
- 空简历模拟有警告
- 实战会话填职位后停止，历史标题正确、仪表盘次数 +1
- 闲聊会话停止，仪表盘次数不 +1

## 8. 完成定义（产品可卖）

同时满足：

1. 新用户能在向导里证明“我听得到面试官”
2. 同一岗位能从简历走到模拟再走到 Copilot
3. 仪表盘数字不再被闲聊污染
4. 有可下载的当前版本安装包和求职季卡购买路径
5. 对外文案与设置页一致：保护有限，规则允许才用

未满足第 1–3 条时，不要做投放。
